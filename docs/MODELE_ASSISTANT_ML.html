1. Objet du document

Ce document décrit le modèle relationnel du module Assistant ML : tables persistées, vues datamart lecture seule, clés étrangères et flux de données.

Il sert à présenter le schéma en réunion (SAQS / métier / technique).

Pour le contexte fonctionnel et les phases P1–P3, voir ASSISTANT_ML.md.

Pour le modèle métier global SIRV2, voir MODELE_DONNEES_SIRV2.md.

Principe : le module ne modifie pas le chemin critique interruptions (saisie, clôture, validation). Il lit les données opérationnelles et produit des scores / suggestions.

2. Glossaire

TermeDéfinition
DatamartVues SQL agrégées en lecture seule sur les incidents (feeder, tronçon SIG, poste)

7. Vues datamart (lecture seule)

7.1 v_ml_incidents_feeder_mois

GrainFeeder × année × mois
Sourcesinterruptions LEFT JOIN feeders
Filtretype_direction = distribution et feeder_id renseigné
Mesuresnb_interruptions, nb_force_majeure, duree_moyenne_minutes, clients_touches_total

7.2 v_ml_incidents_troncon_sig

GrainTronçon SIG (+ feeder / service)
Sourcesinterruption_workflow_steps INNER JOIN interruptions LEFT JOIN troncons_sig
FiltreDistribution + troncon_sig_id renseigné
Mesuresnb_interruptions, duree_moyenne_minutes, derniere_apparition

7.3 v_ml_incidents_poste

GrainPoste impacté
Sourcesposte_interruptions INNER JOIN interruptions LEFT JOIN postes
FiltreDistribution
Mesuresnb_impactes, clients_touches_total, derniere_apparition
Feeder / serviceCOALESCE(pi.feeder_id, p.feeder_id) / COALESCE(pi.service_id, p.service_id)

8. Flux de calcul (P0)

sequenceDiagram participant Admin as Admin_SCR_SAQS participant API as API_assistant participant Celery as Celery_score_feeder_risk participant DB as SQL_Server Admin->>API: POST /assistant/scoring/run API->>Celery: enqueue score_feeder_risk Celery->>DB: lit vues / interruptions Celery->>DB: insert ml_feature_snapshots Celery->>DB: insert ml_predictions is_active Admin->>API: GET /assistant/risk API->>DB: lit ml_predictions
  1. Agrégation sur horizon (défaut 90 j) à partir des incidents distribution.
  2. Écriture d’un snapshot dans ml_feature_snapshots.
  3. Calcul du score P0 (fréquence, permanentes, durée, clients) → ml_predictions.
  4. Affichage UI /assistant et panneau fiche interruption ; chat audité dans assistant_conversations.

9. Périmètre et hors périmètre

Inclus (P0) : tables ci-dessus, vues datamart, scoring règles, audit conversations.

Hors schéma actuel (P1–P3) : tables de modèles entraînés, features spatio-temporelles SIG avancées, stockage embeddings / RAG LLM — à ajouter après validation SAQS.
